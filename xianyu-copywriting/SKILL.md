# 闲鱼学习笔记 PDF 上架文案（黄金案例风格）

## Goal
读取用户提供的自产学习笔记 PDF，产出与黄金案例同等密度和腔调的闲鱼商品文案：100 行左右、8-11 个编号硬技能模块、关键词矩阵、合规声明、交付行——一条文案就能撑起一个完整商品详情页。

## 铁律（违反任何一条即返工）

1. **必须读完全部 PDF**。反面教材：「当前文件内容过长，豆包只阅读了前 20%」——漏读的内容不会出现在文案里，卖点静默丢失。交付前必须核对：已读页数 = PDF 总页数。逐页读、抽样核对章节目录与正文对得上，才算读完。
2. **骨架完全冻结**。段落顺序、各段句式严格按下方模板，只有内容填充变化。禁止增删段落、禁止调整顺序、禁止把声明改成一句温和话——黄金案例的密度就是卖点。
3. **不编造无法反推的事实**。数字类表述（页数、字数、章节数、条目数）尽量从 PDF 实测反推；「全程带截图」必须抽验 PDF 里确实有截图才写；「花费半个月」「两万字」这类体量叙事允许按 PDF 厚度合理推断。查无依据的背书（状元整理、985 学霸）不写。
4. **盗版红线**：商品涉及他人付费资源转卖、代写代做时，拒绝出文案并说明平台风险。

## Workflow

1. **盘点输入**：工作空间下找 PDF（含用户指定的路径）。多份 PDF 放在一起 = 同一系列（用户保证），自动合并为**一条商品**一份文案，不用询问；标题与交付行按系列写法（见 style-guide §多PDF合并）。
2. **读取 PDF**：方式不限——文本抽取、视觉阅读、逐页读均可，Agent 自主决定。读不动时按兜底规则处理（见 style-guide §兜底）：明确报告哪几页读不到，基于已读部分生成并标注推断章节，绝不静默跳过。
3. **提取素材**：从全文提取——完整章节清单、核心技术点名词（命令名/协议名/框架名/工具名）、可复现证据（截图、完整代码、命令可复制）、体量事实（页数、章节数）、目标人群线索。
4. **生成文案**：严格按「冻结骨架模板」+ `references/golden-style-guide.md` 的句式库填充。技术点名词必须来自 PDF 原文，不得臆造名词撑密度。
5. **机器自检**：跑完「自检门禁」清单，不合格逐项修，全部通过才交付。
6. **双输出**：文案全文写入工作空间根目录（文件名 = 笔记主题，如 `ClaudeCode-闲鱼文案.md`；多 PDF 合并也只写一个文件），同时在对话里贴全文方便用户当场改。

## 冻结骨架模板

```
《主标题》
｜副标题：核心技术点罗列，以「完整可复现 / 可落地实战 / 从零精通」类短语收尾

首段（个人整理叙事）：个人XX学习亲手整理的全套笔记，基于XX（来源/教程/工作坊），
从「痛点」到「XX」完整覆盖<罗列覆盖范围>，全程带终端截图、可复制完整命令/代码、
避坑方案，<人群1>、<人群2>、<人群3>直接套用，零基础看完就能XX

笔记的硬核精华兼实战能用的硬技能：
1.【模块名・一句话点题】
- 子弹 5-8 条：技术点 + 短讲解（名词来自 PDF 原文）
2.【模块名・一句话点题】
…（共 8-11 个模块，按 PDF 章节结构组织，前置认知/安装搭建放最前，实战复盘/避坑总结放最后）

重要声明！！！本笔记仅用于XX学习、XX课程实验、技术研究交流，严禁XX（按品类套
style-guide §声明模板，保留原味但罪名列表要贴合笔记主题）

适合群体：
- 4-5 条人群，每条「人群画像 + 具体痛点」

关键词：#词1 #词2 …（15-20 个，精确词+场景词+人群词，见 style-guide §关键词配方）

拍下后发<份数>完整版PDF，不是实物哦～秒发，无延迟直接获取！
```

## 自检门禁（交付前逐项核对，全部 ✅ 才交付）

- [ ] PDF 页数覆盖：已读页数 = 总页数（读不全的地方已在交付时明示）
- [ ] 骨架段落完整且顺序正确：标题/副标题/首段/模块清单/声明/适合群体/关键词/交付行
- [ ] 模块数 8-11；每模块子弹 5-8 条；模块编号连续无重复
- [ ] 技术点名词全部能在 PDF 里找到出处（抽查 5 个）
- [ ] 声明段贴合笔记品类，且保留了「重要声明！！！」原味格式
- [ ] 关键词 15-20 个，三类混合，无同义变体重复
- [ ] 数字类卖点可反推（页数/字数/章节数）或已按体量合理推断
- [ ] 交付行份数正确（单 PDF / 双 PDF / 全套）
- [ ] 自检摘要（一行）附在交付消息末尾
