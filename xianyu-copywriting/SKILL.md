# 闲鱼学习笔记 PDF 上架文案（黄金案例风格）

## Goal

读取用户提供的自产学习笔记 PDF，产出与黄金案例档次相当的闲鱼商品文案：骨架冻结、名词精确、讲解是人话、难点讲得透——一条文案撑起一个完整商品详情页。

**判断标准始终是这一句：跟 `1-5.txt` 那五篇放在一起，像不像同一个作者写的。**

## 铁律（违反任何一条即返工）

1. **必须读完全部 PDF**。反面教材：「当前文件内容过长，豆包只阅读了前 20%」——漏读的内容不会出现在文案里，卖点静默丢失。交付前核对：已读页数 = PDF 总页数。
2. **骨架完全冻结**。段落顺序、各段句式严格按下方模板，只有内容填充变化。禁止增删段落、禁止调整顺序、禁止把声明改成温和话。
3. **不编造无法反推的事实**。页数、字数、章节数这类数字从 PDF 实测反推；「全程带截图」必须抽验 PDF 里确实有截图才写；「花费半个月」这类体量叙事按 PDF 厚度合理推断。查无依据的背书（状元整理、985 学霸）不写。
4. **盗版红线**：涉及他人付费资源转卖、代写代做时，拒绝出文案并说明平台风险。
5. **术语要准、要讲透，不要堆砌**。每条子弹的核心是「一个精确名词 + 一句人话解释」。判断标尺：**一个只会用、不懂原理的人，读完这条能不能多懂一点？** 答「只是把类名排了一遍」就重写。

## 生成前必读（按顺序，三份都要看）

1. **`references/golden-examples.md`** —— **五篇黄金案例完整全文**，必须先通读。这是作者真实发布、市场验证过的文案，不是 AI 示例。读完你对"什么密度、什么语气、一条子弹多长"会有直接的手感，比记住任何规则都管用。
   - 单 PDF 看案例 2（Docker）；多 PDF 合并看案例 3（MCP）；技术名词密集的 Java 类笔记看案例 5（Maven）——它证明术语多不等于名词堆砌。
2. **`references/anti-patterns.md`** —— 真实翻车案例：一份 8,801 字、87 条子弹的失败文案，逐条拆了病因。写的时候对照它，别踩同样的坑。
3. **`references/golden-style-guide.md`** —— 从五案例蒸馏出的句式库、模块写法、术语处理、声明模板、关键词配方、兜底规则。

## Workflow

1. **盘点输入**：工作空间下找 PDF（含用户指定路径）。多份 PDF 放在一起 = 同一系列（用户保证），自动合并为一条商品一份文案，不用询问。
2. **读取 PDF**：方式不限，Agent 自主决定。读不动时按兜底规则处理（见 style-guide §九），明确报告哪几页读不到，绝不静默跳过。
3. **提取素材**：完整章节清单、核心技术点名词、可复现证据（截图/完整代码/命令）、体量事实、目标人群线索。**同时标出这份笔记最值钱的 2–3 个难点**——那是首段钩子的原料。
4. **生成文案**：按「冻结骨架模板」+ style-guide 句式库填充。名词必须来自 PDF 原文，但**用中文讲，英文名词只做索引**（详见 style-guide §三）。
5. **机器体检**：跑 `python scripts/gate.py <文案文件>`，对照五案例实测分布检查密度与手感。出带的项逐条改，全绿再交付。
6. **双输出**：文案全文写入工作空间根目录（文件名 = 笔记主题，如 `ClaudeCode-闲鱼文案.md`），同时在对话里贴全文方便用户当场改。

## 冻结骨架模板

```
《主标题》
｜副标题：核心技术点罗列，以「完整可复现 / 可落地实战 / 从零精通」类短语收尾

首段（个人整理叙事）：个人XX学习亲手整理的全套笔记，基于XX（来源/教程/工作坊），
从「痛点」到「XX」完整覆盖<罗列覆盖范围>，全程带终端截图、可复制完整命令/代码、
避坑方案，<人群1>、<人群2>、<人群3>直接套用，零基础看完就能XX

笔记的硬核精华兼实战能用的硬技能：
1.【模块名・一句话点题】
- 子弹：技术点 + 短讲解（名词来自 PDF 原文，讲解 25-40 字）
2.【模块名・一句话点题】
…（按 PDF 章节结构自然切分，不硬凑数量，前置认知放最前，实战复盘/避坑总结放最后）

重要声明！！！本笔记仅用于XX学习、XX课程实验、技术研究交流，严禁XX（按品类套
style-guide §四声明模板，保留原味但罪名列表要贴合笔记主题）

适合群体：
- 4-5 条人群，每条「人群画像 + 具体痛点」

关键词：#词1 #词2 …（15-20 个，精确词+场景词+人群词，见 style-guide §六）

拍下后发<份数>完整版PDF，不是实物哦～秒发，无延迟直接获取！
```

## 交付前自检

**第一步：跑机器体检**

```bash
python scripts/gate.py <文案文件>
```

它会对照五篇黄金案例的真实分布（不是拍脑袋的阈值）检查：全文体量、模块数、子弹数、单条长度、超长条数、英文占比、每条例词数，以及方法签名串 / XML 标签 / 直角引号 / 箭头链。

**硬信号出带 = 必须返工**（方法签名串、XML 标签、直角引号在五案例 318 条子弹里出现 0 次）；体量项只是参考，PDF 章节厚薄不同可以忽略。脚本会分行标出来。

**第二步：人工过三问**

- [ ] **骨架齐不齐**：标题 / 副标题 / 首段 / 模块清单 / 声明 / 适合群体 / 关键词 / 交付行，八段齐全且顺序无误
- [ ] **像不像内行**：随机抽 5 条子弹，问「只会用不懂原理的人读完能多懂一点吗」——答不上就重写
- [ ] **名词真不真**：抽查 5 个技术名词，全部能在 PDF 原文里找到出处

**第三步：交付消息末尾附一行摘要**

`✅ 自检：骨架完整｜9模块｜关键词18｜3,120字｜已读42/42页`
