# 黄金案例风格指南（五案例蒸馏）

蒸馏自工作空间的五篇黄金案例：1.txt《Claude Code》、2.txt《Docker》、3.txt《MCP》、4.txt《LangChain》、5.txt《Maven》。生成前先通读 `golden-examples.md` 找手感，再扫一遍 `anti-patterns.md` 避开翻车点。

> 本指南里的数字全部来自五篇原文实测，不是设定值。想核对任何一条，跑 `scripts/gate.py`。

## 一、标题与副标题

- 主标题：`《主题 + 从0到1/全套 + 定位词》`，如《Docker从0到1保姆级全套实战笔记》《韩顺平-Maven 全套实战笔记》。带教程出处时保留（韩顺平-）。
- 副标题独占一行，以 `｜` 开头：核心技术点用 `｜` 罗列 5-8 个，以「完整可复现」「可落地实战」「从零精通Maven 工程化必备」这类可复现承诺收尾。
- 副标题是搜索优化位：塞买家会搜的技术词（MCP协议原理 / 镜像分层 / RAG智能体）。

## 二、首段（个人整理叙事，一个长句群）

固定要素按序拼装：

1. 身份叙事：「个人XX学习亲手整理的全套笔记」/「个人花费半个月整理两万字XX图文笔记」
2. 来源背书：「基于XX系统/教程/技术工作坊完整实操整理」「逐字梳理」
3. 覆盖范围罗列：「从A、B，到C、D、E全模块手把手教学」（把 PDF 章节名压缩塞进来）
4. 过程承诺：「全程附带终端截图、可复制完整命令、报错排坑方案」
5. 使用场景 + 零基础承诺：「课程实验、毕业设计、自学练手直接照搬，零基础看完就能独立XX」

**首段是钩子不是摘要**：黄金案例首段 153–226 字。可以点出这份笔记最值钱的 2-3 个难点（"容器结构、代理链、事务传播失效这三处最容易卡壳的地方都掰开揉碎讲了"），但不要罗列完整目录——那是反面案例里的错误写法。

体量叙事（花费半个月 / 两万字 / 15页）按 PDF 实际厚度合理推断：厚 PDF 才写两万字，能数出页数就写页数。

## 三、模块清单（文案的脊柱）

固定引导句：`笔记的硬核精华兼实战能用的硬技能：`

- **按 PDF 章节结构自然切分**。五案例是 9-11 个模块、每模块 4-7 条子弹，但那是 PDF 章节撑起来的，不是硬凑的。章节少的 PDF 就少写几个模块；章节多就合并同类。**唯一禁止的是把一条子弹拆成两条凑数。**
- 模块标题：`N.【模块名・一句话点题】`，模块名 4-10 字，点题短语补充定位。常见序列：
  - 开头：前置认知/基础扫盲（`1.【前置名词体系・彻底分清XX】`）
  - 中段：环境搭建安装避坑 → 各核心技术模块逐个展开 → 实战案例 1、2…
  - 结尾：完整项目复盘 / 踩坑总结与最佳实践（`10.【全套实操踩坑总结+生产最佳实践】`）
- 每模块 4-7 条子弹。**单条 25-40 字为常态，超过 45 字要慎重**——只有无法拆分的并列清单（Docker 的八大指令、Maven 的五条命令）才允许长条，全案控制在 7 条以内。

### 子弹怎么写（这一节最重要）

一条子弹 = **一个精确名词 + 一句人话解释**。

```
- 名词/技术点：它是什么、怎么用、为什么 → 读者看完多懂一点
```

**术语处理的三条原则：**

1. **名词要精确**：来自 PDF 原文的命令名、协议名、类名、参数名。这是可信度的来源，也是闲鱼搜索的命中点。
2. **讲解说人话**：冒号右边必须是能读懂的中文，不是签名串。对比：

   | ❌ 反面案例 | ✅ 黄金案例写法 |
   |---|---|
   | `生命周期 11 步：构造器 → 属性注入 → Aware 回调 → postProcessBeforeInitialization → afterPropertiesSet → ...`（178 字） | `生命周期：实例化、属性注入、初始化、销毁四大阶段，BeanPostProcessor 全程可插拔`（38 字） |
   | `Debug 看容器四大件：beanFactory（DefaultListableBeanFactory）、beanDefinitionMap（存 BeanDefinition）...` | `Debug 看容器四大件：BeanFactory、BeanDefinition 映射、单例池、名称列表` |
   | `自动装配与 SpEL：autowire 的 no/byName/byType/constructor/default 五种模式与 primary...` | `自动装配五种模式：按名、按类型、按构造器全覆盖，冲突交给首选标记破解` |

3. **英文词是索引不是密度**：黄金案例英文占比 20%-38%，比想象的高；但**每条例词中位数只有 1-2 个**——一个精确名词，其余全是中文。反面案例是 5 个一组的枚举词把句子埋了。

**四条硬信号（五案例 318 条子弹里出现 0 次，出现即返工）：**

- `方法名()` 签名串 —— 不要在正文里写 `postProcessAfterInitialization()`
- `<XML 标签>` —— 写"用属性标签"而不是列出 `<bean><property>`
- `「」` 直角引号 —— 中文引号用「」以外的写法或直接不用
- 冒号右边塞长括号 —— 黄金案例括号内容只占 0%-2.1%，反面案例是 6.9%

`→` 箭头**允许但限量**：只在"顺序/层级"类内容里用，全案不超过 11 次（Maven 案例的用法）。不能拿箭头承载整条逻辑。

- 实战类模块用「步骤链」写法：每条子弹是流程的一步（搜索→拉取→启动→验证→修改→访问测试）。
- 子弹里可穿插 ①②③ 编号列举（三种挂载模式、四大网络模式）。

## 四、重要声明段

格式冻结：`重要声明！！！本笔记仅用于<合规用途罗列>，严禁<对应违规行为>！<限定环境句>，违规操作后果自行承担/仅用于学习提升使用。`

- 保留「重要声明！！！」的感叹号原味——这是风格的一部分，不许改成温和句。
- 用途与罪名必须**贴合笔记主题**：Nmap 笔记禁「未授权扫描」，Docker 笔记禁「搭建非法服务」，LangChain 笔记禁「违规AI应用开发」。从 PDF 内容推断对应红线，不套万能模板。

## 五、适合群体

- 标题行 `适合群体：`，4-5 条，每条格式 `- <专业/身份画像>：<具体痛点或用途>`。
- 画像带专业名（计算机/软件工程/AI专业学生）、痛点带具体场景（不会容器部署、被Jar包版本冲突折磨、看不懂扫描结果）。
- 每条 32-38 字（五案例实测），别写成简历。
- 最后一条通常是「想系统掌握XX的技术爱好者」收尾。

## 六、关键词行

- 单行 `关键词：#词1 #词2 …`，**15-20 个**，空格分隔。
- 三类混合：
  - 精确词：技术名、工具名、章节名（Docker、Dockerfile、pom.xml、JSON-RPC）
  - 场景词：后端开发、运维学习、AI应用、实验报告
  - 人群词：学生党笔记、编程电子资料、大学学习、学习笔记
- 同义变体只留一个；核心主题词必须出现；「#学习笔记 #电子资料」类通用词 2-3 个即可。

## 七、交付行（冻结）

`拍下后发完整版PDF，不是实物哦～秒发，无延迟直接获取！`

- 单份：`拍下后发电子版 PDF笔记，不是实物哦～秒发，无延迟直接获取！`
- 多份合并：`拍下后发送**基础篇+进阶篇两份完整版PDF**，不是实物哦～秒发，无延迟直接获取！`（份数与各份名称写明）

## 八、多 PDF 合并（同系列）

- 工作空间同批出现的 PDF 默认同一系列，合并为一条商品一份文案，不询问。
- 合并写法：标题取系列总主题；首段可写「合并**基础篇+进阶篇**两大文档」（参照案例 3）；交付行按第七节多份模板；模块清单合并两份 PDF 的章节统一编排编号。

## 九、兜底规则（PDF 读不全时）

1. 文本抽取读不出（扫描版/图片版）→ 自动转图片逐页视觉阅读，不安装 OCR、不卡死。
2. 个别页仍读不出（模糊/加密）→ 明确报告「第 X-Y 页未能读取」，基于已读部分生成；对应章节用章节标题做模块名、子弹降密度，并在交付时标注哪些模块是推断补全。
3. 绝不静默跳过：交付消息必须写明「已读 X/X 页」。

## 十、输出规则

- 文案全文写入工作空间根目录，文件名 = 笔记主题：`ClaudeCode-闲鱼文案.md`、`Docker-闲鱼文案.md`。多 PDF 合并也只写一个文件。
- 对话里同时贴全文，方便用户当场改。
- 交付前跑 `scripts/gate.py <文案文件>`，出带的项改到全绿。
- 交付消息末尾附一行自检摘要：`✅ 自检：骨架完整｜9模块｜关键词18｜3,120字｜已读42/42页`。
- 案例文件中的「当前文件内容过长，豆包只阅读了前 X%」是工具残渣，蒸馏与产出时一律剔除，绝不出现在文案里。
